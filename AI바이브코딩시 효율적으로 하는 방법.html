AI에게 코딩 시킬 때
덜 헤매는 법

코딩을 배우지 않아도 AI로 프로그램을 만들 수 있는 시대입니다. 다만 요청하는 방식에 따라 걸리는 시간이 몇 배씩 차이 납니다. 이 문서는 그 차이를 만드는 요령만 모았습니다.

AI는 당신의 머릿속을 못 봅니다. 본 것만 알고, 말한 것만 압니다.

1잘 되다가 갑자기 멍청해지는 이유

원리 하나만 알면 나머지 요령이 다 이해됩니다.

AI는 사람처럼 기억하지 않습니다. 질문을 받을 때마다 그 대화의 처음부터 끝까지를 다시 읽고 답합니다. 40번째 질문에 답하려면 앞의 39번을 통째로 다시 읽는 셈입니다.

그래서 대화가 길어지면 이런 일이 생깁니다.

  • 답변이 느려집니다
  • 아까 시킨 걸 까먹거나, 반대로 아까 지운 걸 되살립니다
  • 고치지 말라고 한 부분을 자꾸 건드립니다
  • 유료 요금제라면 사용량이 훨씬 빨리 소진됩니다

읽어야 할 양이 늘어날수록 집중력이 흐려지는 겁니다. 그러니 요령의 핵심은 하나입니다. AI가 읽어야 할 양을 줄여주는 것. 앞으로 나올 내용은 전부 이 한 문장의 응용입니다.

2시작 전 30초, 세 가지만 정하기

이걸 안 정하고 시작하면 나중에 처음부터 다시 만들게 됩니다.

어디서 실행할 건가

비전공자가 가장 많이 겪는 사고가 이겁니다. 뭔가 만들어졌는데 내 컴퓨터에서 열 방법이 없는 것. AI는 물어보지 않으면 개발자용 환경을 기본으로 가정합니다. 먼저 말해주세요.

  • 가장 쉬운 길 — "더블클릭하면 크롬에서 바로 열리는 HTML 파일 하나로 만들어줘"
  • 설치가 필요하면 — "설치 과정을 초보자 기준으로 하나씩 알려줘"

한 번에 하나만

"로그인도 되고 게시판도 있고 알림도 오게 해줘"는 실패합니다. 한 덩어리로 만들어진 것은 어디가 고장 났는지 찾을 수가 없습니다. 기능 하나가 완전히 작동하는 걸 확인한 뒤에 다음으로 넘어가세요.

완성됐다는 걸 어떻게 알 건가

"예쁘게 만들어줘"는 끝이 없습니다. "버튼을 누르면 입력한 이름이 아래 목록에 추가되고, 새로고침해도 남아 있으면 완성"처럼 눈으로 확인 가능한 문장으로 정하세요. 이게 있어야 AI도 멈출 지점을 압니다.

3요청에 반드시 들어가야 할 네 가지

길게 쓸 필요는 없습니다. 빠진 게 없으면 됩니다.

좋은 요청은 네 조각으로 되어 있습니다. 목표(뭘 만들지), 제약(건드리면 안 되는 것), 형식(어떤 모양으로 받을지), 완료 조건(뭐가 되면 끝인지).

이렇게 쓰면

"방문자 기록하는 기능 좀 예쁘게 넣어줘"

이렇게 씁니다

"이름과 방문 날짜를 입력해 목록에 쌓는 기능을 추가해줘. 기존 디자인과 다른 기능은 그대로 둘 것. 수정된 부분만 어디에 넣을지 표시해서 보여줘. 새로고침해도 목록이 남아 있으면 완성이야."

특히 형식을 빼먹는 분이 많습니다. 그냥 두면 AI는 파일 전체를 처음부터 끝까지 다시 뱉어냅니다. 매번 몇백 줄을 다시 받아 통째로 갈아끼우는 건 시간 낭비이자 사고의 원인입니다.

  • 고칠 데가 한두 군데 — "바뀐 부분만, 앞뒤 세 줄과 함께 보여줘"
  • 구조가 바뀌는 큰 작업 — "전체 파일로 다시 줘" (이땐 부분만 받으면 붙여넣다가 깨집니다)

4파일을 쪼개면 절반이 해결됩니다

프롬프트 기술보다 효과가 큽니다.

모든 걸 파일 하나에 넣어두면, 글자 색 하나 바꾸려고 매번 전체를 통째로 올려야 합니다. AI 입장에선 매번 책 한 권을 다 읽고 오탈자 하나를 고치는 셈입니다.

처음 만들 때부터 이렇게 나눠달라고 하세요.

  • 화면 뼈대 — 어떤 요소가 어디 있는지
  • 디자인 — 색, 크기, 여백
  • 동작 — 버튼을 누르면 무슨 일이 일어나는지
  • 내용물 — 목록, 표, 문구 같은 데이터

나눠두면 "색깔 바꿔줘"에는 디자인 파일만 올리면 됩니다. 다른 파일은 보여주지도 않았으니 건드릴 수가 없습니다. "기존 코드 건드리지 마"라고 사정할 필요가 사라지는 겁니다.

이미 한 덩어리로 만들어버렸다면, 지금이라도 "기능은 그대로 두고 파일만 네 개로 분리해줘"라고 한 번 요청하세요. 한 번 고생하면 이후가 편해집니다.

5매번 쓰는 말은 설정에 박아두기

같은 잔소리를 매 대화마다 반복하고 있다면.

ChatGPT의 맞춤 설정이나 프로젝트 기능에 규칙을 한 번 넣어두면 모든 대화에 자동으로 적용됩니다. 매번 타이핑하지 않아도 됩니다.

맞춤 설정에 넣을 규칙
나는 코딩 비전공자다. 아래 규칙을 항상 지켜줘.

- 내가 지시한 부분 외의 기존 코드, 디자인, 데이터는 절대 수정하지 마
- 요청하지 않은 개선이나 정리는 하지 마
- 전문 용어를 쓸 때는 괄호 안에 쉬운 설명을 붙여줘
- 코드 설명은 세 줄 이내로, 무엇이 바뀌었는지만
- 파일에 저장해야 하는 코드는 어느 파일 어디에 넣는지 명확히 알려줘
- 확실하지 않으면 추측하지 말고 나에게 물어봐

마지막 줄이 특히 중요합니다. AI는 모를 때 모른다고 하기보다 그럴듯하게 지어내는 성질이 있습니다. 미리 물어보라고 해두면 헛수고가 줄어듭니다.

6대화가 길어지면 갈아타세요

한 대화에서 끝까지 버티는 게 미덕이 아닙니다.

1번에서 설명한 이유로, 30턴쯤 지난 대화는 처음보다 훨씬 둔해집니다. 슬슬 이상한 답이 나오기 시작하면 대화 실력이 문제가 아니라 대화가 길어서 그런 겁니다.

기능 하나가 끝나면 새 대화를 여세요. 대신 인수인계 메모를 맨 앞에 붙여주면 됩니다.

새 대화 시작 메모
[지금까지 상황]
- 만들고 있는 것 : (예: 동호회 회비 관리 페이지)
- 파일 구성 : index.html / style.css / script.js
- 완료된 기능 : 회원 목록 표시, 회비 입력
- 이번에 할 일 : 미납자만 따로 걸러서 보여주기
- 건드리지 말 것 : 그 외 전부

관련 파일만 아래에 첨부할게. 위 내용만 참고해서 작업해줘.

7에러가 났을 때

비전공자가 가장 많이 포기하는 지점입니다.

에러 메시지는 요약하지 말고 그대로

"오류가 났어요"는 정보가 없습니다. 빨간 글씨 전체를 그대로 복사해서 붙여넣으세요. 알아들을 수 없어도 상관없습니다. AI에게는 그게 가장 정확한 단서입니다.

브라우저에서 만든 거라면 F12를 눌러 Console 탭을 여세요. 화면엔 안 보이던 오류가 거기 적혀 있습니다.

"안 돼요" 대신 세 문장으로

이렇게 쓰면

"안 되는데요? 고쳐주세요"

이렇게 씁니다

"저장 버튼을 눌렀더니 화면이 하얗게 변했어. 목록에 이름이 추가되길 기대했어. F12 콘솔에 뜬 빨간 글씨는 아래와 같아."

무엇을 했고, 무슨 일이 일어났고, 무엇을 기대했는지. 이 세 가지면 충분합니다.

세 번 고쳐도 안 되면 멈추세요

같은 문제로 네 번째 수정에 들어가면 대개 코드가 더 망가집니다. AI가 앞선 수정 위에 또 수정을 얹으면서 엉키기 때문입니다. 그럴 땐 마지막으로 정상 작동하던 상태로 되돌린 뒤, 새 대화에서 처음부터 다시 요청하는 편이 훨씬 빠릅니다.

8되돌아갈 자리를 만들어두기

이것만 해도 밤새 만든 걸 날리는 일은 없습니다.

개발자들은 버전 관리 도구를 쓰지만, 비전공자는 폴더 복사만으로도 충분합니다.

  • 잘 작동하는 상태가 되면 폴더를 통째로 복사해두세요
  • 폴더 이름은 날짜와 상태로 — 0904_회비목록까지_정상
  • 최종, 진짜최종, 최종2는 나중에 본인도 못 알아봅니다

중요한 작업이면 클라우드 폴더(구글 드라이브 등) 안에서 작업하세요. 파일 우클릭으로 이전 버전을 되살릴 수 있습니다.

9하면 안 되는 것들

여기서 사고가 납니다.

알아서 해줘 — AI는 빈칸을 자기 마음대로 채웁니다. 마음에 안 들면 처음부터 다시 하게 됩니다.
한 번에 기능 여러 개 — 고장 나면 어디가 원인인지 영영 못 찾습니다.
비밀번호나 인증키를 코드에 그대로 적기 — 인터넷에 올리는 순간 누구나 볼 수 있습니다. 비밀 정보는 코드에 넣지 말고 AI에게도 알려주지 마세요.
잘 돌아가는 코드에 "더 좋게 해줘" — 멀쩡한 걸 갈아엎다가 망가집니다. 불만이 있으면 어디가 어떻게 불만인지만 짚어주세요.
내용을 확인 안 하고 그냥 붙여넣기 — 최소한 이 코드가 뭘 하는 건지 한 줄 설명은 받고 넣으세요.
실행 결과를 안 보고 다음 요청 — 한 단계씩 눈으로 확인하고 넘어가야 합니다.
남의 개인정보를 그대로 올리기 — 실제 이름, 연락처, 계좌 대신 가짜 예시로 바꿔서 올리세요.

10복사해서 쓰는 템플릿

괄호 안만 바꿔서 그대로 쓰시면 됩니다.

① 처음 만들기 시작할 때
나는 코딩을 전혀 모르는 비전공자야. 아래 조건대로 만들어줘.

만들 것 : (무엇을 하는 프로그램인지 두세 줄로)
쓸 사람 : (나 혼자 / 우리 팀 / 불특정 다수)
실행 환경 : 더블클릭하면 크롬에서 바로 열리는 형태로
파일 구성 : 뼈대, 디자인, 동작, 데이터를 각각 다른 파일로 나눠줘
완료 조건 : (이게 되면 완성이라고 할 수 있는 것)

지금은 첫 단계만 만들어줘. 화면에 (   )가 보이는 것까지만.
파일마다 어떤 이름으로 어디에 저장하는지도 알려줘.
② 기능을 추가할 때
추가할 기능 : (무엇이 되게 하고 싶은지)
동작 방식 : (어디를 누르면 무엇이 일어나야 하는지)
건드리지 말 것 : 지금 잘 되고 있는 다른 기능과 디자인 전부
받을 형식 : 수정된 부분만, 앞뒤 세 줄을 포함해서
완료 조건 : (눈으로 확인할 수 있는 기준)

관련된 파일만 첨부했어. 첨부한 파일 안에서만 작업해줘.
③ 에러가 났을 때
내가 한 것 : (어느 버튼을 눌렀는지, 무엇을 입력했는지)
일어난 일 : (화면이 어떻게 됐는지)
기대한 것 : (원래 어떻게 되어야 했는지)

에러 메시지 (F12 콘솔에서 그대로 복사) :

원인부터 한 문장으로 알려주고, 그다음 고친 부분만 보여줘.
④ 코드가 엉켰을 때 되돌리기
지금까지 여러 번 고치면서 코드가 엉킨 것 같아.
마지막으로 정상 작동하던 파일을 다시 올릴게.

이 파일을 기준으로 다시 시작하자.
앞선 대화에서 시도했던 수정은 전부 무시해줘.

이번에 할 일은 (   ) 하나뿐이야.
⑤ 이해가 안 될 때
방금 준 코드를 비전공자가 알아들을 수 있게 설명해줘.

- 이 코드가 전체적으로 무슨 일을 하는지 한 문단
- 내가 나중에 직접 바꿔볼 만한 부분이 있다면 어디인지
- 절대 건드리면 안 되는 부분이 있다면 어디인지

전문 용어는 괄호 안에 쉬운 말로 풀어서 써줘.

기억할 것은 다섯 개

세부 요령이 헷갈릴 땐 이것만 지켜도 대부분 해결됩니다.

  1. 한 번에 기능 하나씩, 확인하고 넘어가기
  2. 파일을 쪼개서 고칠 것만 보여주기
  3. 완료 조건을 눈으로 볼 수 있는 문장으로 정하기
  4. 대화가 길어지면 새 대화로 갈아타기
  5. 잘 될 때마다 폴더 복사해두기
